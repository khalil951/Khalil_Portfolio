## TL;DR

- **Problem:** RFC's Xpress PPM (Dynamics 365 / Power Platform) needed AI-assisted project-request intake and triage, made urgent by Microsoft Project Online's retirement on September 30, 2026.
- **What I built:** A <Term id="hybrid-architecture">hybrid</Term> two-tier gate-approval agent — Copilot Studio for the conversation, a 5-node LangGraph pipeline for deterministic decisions — flagship of a larger 17-agent tiered portfolio design.
- **Outcome:** An MVP with a 102-test offline suite; a full evaluation run (LLM-as-judge, BLEU/ROUGE, cross-model agreement, latency) that hasn't been exported yet.

## Problem & constraints

Xpress PPM needed project-request intake and triage assisted by AI, without handing a language model unilateral authority over gate decisions. The retirement of Microsoft Project Online on September 30, 2026 made the timeline non-negotiable.

## Architecture

Two tiers, each doing what it's good at:

- **Tier 1 — Microsoft Copilot Studio**, the conversational surface a project owner interacts with.
- **Tier 2 — LangGraph + FastAPI**, autonomous and deterministic. Its flagship is the **Gate Approval Agent (C1)**, a 5-node LangGraph pipeline.

Five <Term id="guardrails">deterministic guardrail rules</Term> can block a request outright, overriding whatever the LLM concluded. Output is Pydantic-validated against a fixed schema, and a 4-model OpenRouter <Term id="fallback-chain">fallback chain</Term> keeps the pipeline answering if a model endpoint is down. A synthetic PostgreSQL dataset (50 records) mirrors the real `msdyn_project` / `msdyn_projectrequest` schema, and a three-interface Streamlit app demonstrates the flow end to end.

C1 is one tier of a larger, only-partly-built design: a 17-agent tiered portfolio scoped against Planner Premium's gaps, of which only C1 ships today.

## Key decisions & tradeoffs

- **Hybrid over all-Copilot-Studio.** An earlier all-conversational design couldn't guarantee determinism or testability. Splitting the conversational and decision tiers made both properties possible.
- **Guardrails outrank the model.** The five blocking rules are checked in code, not asked of the LLM — a request that fails one is rejected regardless of what the model would have said.
- **Verify endpoints before finalizing a fallback chain.** Two of the original fallback models turned out to have no live endpoints and were swapped out — a lesson about validating a chain's assumptions before relying on them.
