## Implementation corrections (found while building, vs. the original research)
- **Velite hook is `prepare`, not `complete`.** Checking `node_modules/velite/dist/index.d.ts` directly: `complete` is a post-build side-effect-only hook (data is already written by the time it runs); `prepare` is the one that can mutate data and fail the build (`Promisable<void | false>`, run "before write to file"). All cross-collection validation (stack/concepts/`<Cite>`/`<Term>`/epigraph id resolution, draft-margin-note check) lives in `scripts/velite-prepare.ts`, wired via `prepare:` in `velite.config.ts`.
- **No custom remark plugin.** Velite's `prepare`/`complete` hooks receive fully-compiled `Result<T>` data, not per-file vfile.data from a remark pass, without deeper (unverified) internals. Instead, both `Chapter` and `Section` schemas carry `raw: s.raw()` (the original MDX source), and `velite-prepare.ts` regex-scans `raw` for `<Cite id>`, `<Term id>` and `<MarginNote draft>`. Still single-source-of-truth and build-fails on a bad id — just implemented as a regex pass over raw source rather than an AST plugin. `reading-time`, `js-yaml`, `unist-util-visit`, `mdast-util-to-string` were dropped from dependencies as a result (Velite's built-in `s.metadata()` already gives `{readingTime, wordCount}`; YAML collections are parsed by Velite's built-in loader).
- **`Chapter.epigraph` is optional**, not required as docs/05's schema literally shows. Three chapters (II, V, VI) have no epigraph candidate at all in docs/07 (only a research prompt, no quote text) — forcing a required field would mean inventing a placeholder id. `velite-prepare.ts` validates that when `epigraph` *is* set, it resolves to a real `epigraphs.yaml` id (this caught a real authoring bug: Chapter II's MDX briefly had `epigraph: "ch2"` pointing at a non-existent entry — fixed and now guarded).
- **`Section` schema gained an optional `safety` field**, not in docs/05's literal schema. CLAUDE.md rule 7 requires the Breast Cancer project's safety disclaimer to be "a required, visible field" — CLAUDE.md outranks docs/05 in the priority order, so the schema was extended rather than folding the disclaimer into free-form body prose.
- **`eslint` pinned to `9.39.5`, not `10.11.0`.** `eslint-config-next@16.3.6`'s bundled `eslint-plugin-react@7.37.5` calls the removed ESLint 8-era `context.getFilename()` API and crashes under ESLint 10 (`contextOrFilename.getFilename is not a function`) on every file, including config files — a genuine upstream compatibility gap, not a bug in this repo. 9.39.5 is past its official support window but is the newest version the toolchain actually works with; revisit once `eslint-plugin-react`/`eslint-config-next` catch up to ESLint 10's context API.
- **`RootLayout`'s props type is `{ children: ReactNode }`, not Next's generated `LayoutProps<"/">`.** That helper type only exists after Next has generated `.next/types/**`, which happens during `next dev`/`next build` — a standalone `tsc --noEmit` (the typecheck gate) needs to work without a prior build having run.
- **ThemeToggle uses `useSyncExternalStore`**, not `useState` + `useEffect`, to read `document.documentElement`'s `data-theme` (already set by the pre-paint inline script). The eslint-plugin-react-hooks `set-state-in-effect` rule flags the `useEffect`-based version; `useSyncExternalStore` is the correct pattern for syncing with an external (non-React) source and handles the server/client snapshot divergence safely.

## Phase 5 implementation notes
- **`next/og`'s `ImageResponse` and `sitemap.ts`/`robots.ts` all needed `export const dynamic = "force-static"`** to work under `output: 'export'` — without it, `next build` fails outright ("export const dynamic = force-static/revalidate not configured... with output: export"). Found by just running the build, not by reading ahead; fixed on all five files (root + 2 chapter-level OG images, sitemap, robots).
- **The production domain is genuinely unknown** (docs/06 "Still open: Domain name") — `sitemap.xml`/`robots.txt`/OG `metadataBase` all read `NEXT_PUBLIC_SITE_URL`, falling back to `https://example.com` locally (`lib/site.ts`). Must be set as a real env var at deploy time; nothing here guesses a domain.
- **The View Transitions "InvalidStateError" investigation.** Manual rapid/overlapping-click testing occasionally logged `InvalidStateError: Transition was aborted because of invalid state` to console. Isolated with clean single-navigation tests (via `page.evaluate` clicks, not mouse-coordinate automation) run twice — zero errors both times — then tried to force it with a deliberate synchronous double-navigation, which *also* didn't reproduce it. Conclusion: this is the browser's own well-documented behavior when a view transition is genuinely interrupted mid-animation by a newer one (a real risk only under very fast repeat navigation), not a bug introduced here, and it never appeared in the full Lighthouse "errors in console" audit (which loads each page fresh, no navigation) or the Playwright suite. Not fixed further; documented instead of chased.
- **Grid overflow bug found in the Phase 5 e2e audit, not before**: the Phase 2/3 margin-column technique (float + negative margin, "escape into extra viewport space beyond the container") mathematically cannot work at viewport widths where the container's own max-width leaves no real gutter outside it — confirmed with a real MiniMap on a real page at exactly 1280px, overflowing by ~280px. Rebuilt as a genuine 3-column CSS Grid (TOC | text | margin, every track hard-capped) instead — impossible to overflow, since a grid with only capped tracks can never render wider than the sum of its tracks. MiniMap is now a real third grid-column child (`ChapterLayout`'s new `marginContent` prop), not a floated descendant of the article. MarginNote (still zero real instances) was simplified to an always-inline indented aside rather than chasing the same float trick for content that doesn't exist yet.
- **WCAG 2.2 AA 2.5.8 Target Size, found by the axe audit on nearly every compact link list on the site** (Cover's key-facts, Connections, the Index, Contents, chapter TOC, nav — anywhere a `text-sm` link had no padding, ~16-17px tall). First attempt paired padding with an equal negative margin to keep layout pixel-identical — that backfired in tightly-gapped lists: adjacent targets' padding boxes overlapped, which axe reports as `partiallyObscured` (an overlapping hit area isn't a clean, unambiguous 24px target even when the CSS box itself is big enough). Fixed by dropping the negative margin entirely (`.tap-target` in globals.css) — the same padding-only pattern already used by `SkillGroups`' chips, which the audit never flagged. The small extra breathing room in these lists is a fine, honestly-arrived-at trade for a real fix, not a cosmetic regression.
- **`role="img"` on the Map's `<svg>` was semantically wrong** once individual nodes became keyboard-focusable (`tabindex=0 role="button"`) — `role="img"` asserts "treat this as one flat, non-interactive image," which axe correctly flags as invalid when the element has focusable descendants. Changed to `role="group"`. MiniMap hit the adjacent, more specific rule (`aria-prohibited-attr`): `aria-label` on an `<g>` needs *some* explicit role to be valid at all — added `role="img"` there instead, correctly, since MiniMap's non-linked nodes (unlike the full Map's) aren't interactive.
- **Lighthouse best-practices sat at 96, not 100, until traced to `errors-in-console`**: every visible `<Link>` was triggering Next's default RSC-payload prefetch (`__next.<route>.__PAGE__.txt`), which 404s on every single page load because `output: 'export'` never generates those files — there is no server, ever, to produce them on this deployment target. A thin wrapper (`components/Link.tsx`) defaults `prefetch={false}` and is now imported everywhere instead of `next-view-transitions`'s `Link` directly; this is a correct fix, not a lost optimization, since the prefetch capability doesn't exist for a fully static export regardless. Re-ran Lighthouse after the fix: 100/100/100/100 on Cover, a chapter, and `/map`.
- **Playwright's default parallelism overloaded this sandboxed dev machine, not the site.** At `fullyParallel: true` with the default worker count, 20-40 tests failed with "Test timeout... page.goto" — but every single one of those exact tests passed in under 2 seconds when rerun individually or with `workers: 1`. Verified this conclusion twice (isolated reruns of "failing" tests, and a deliberate attempt to reproduce resource contention) before trusting it rather than chasing phantom bugs. `workers: 1` is the setting now committed — slower, but the only one that was reliably clean here; documented as machine-specific, safe to raise on a more capable CI runner.
- **Final verified state**: 61/61 Playwright tests pass (32 axe scans — Cover/chapter/project/map × light/dark × 360/768/1280/1920, all zero violations; full keyboard-only walkthrough; zero horizontal overflow at any tested breakpoint; key facts visible without scrolling at 1280×720 on Cover and Contents; zero console errors in either theme). ## Phase 4 implementation notes
- **`forceLink()` silently mutates `edge.source`/`edge.target` from string ids into the actual node objects** as a side effect of running the simulation — this is documented d3 behaviour, but it broke every downstream `nodeById.get(edge.source)` lookup, so the Map initially rendered all 76 nodes with **zero visible edges** and no error of any kind (the code just silently filtered every edge out via `if (!source || !target) return null`). Caught by looking at the actual rendered screenshot, not by the build passing. Fixed by normalizing edges back to `{source: string, target: string}` at the end of `layoutGraph()`, so the `GraphEdge` type's documented contract holds for every consumer.
- **`forceCenter` does not re-center individual nodes** — it only shifts the whole layout by a constant offset each tick so the *average* position matches the target. A node with no or few edges (Chapter V "Foundations", Chapter VII "Open Questions" — both genuinely link to nothing else in their own content) drifted to (10823, 3700) on an 800×600 canvas under pure charge repulsion, i.e. completely outside the viewBox. Fixed with a weak `forceX`/`forceY` "gravity" toward center (strength 0.12) — standard practice for d3-force graphs that may have disconnected components, confirmed by rerunning the layout standalone via `tsx` and checking the coordinate bounds before ever touching the browser.
- **`next/link` is not used inside the graph's `<svg>`** — `<Link>`'s prefetch/transition logic assumes an `HTMLAnchorElement`; inside an `<svg>` subtree React renders `<a>` in the SVG namespace instead. Plain `<a href>` is used for node navigation in both `MapExplorer` and `MiniMap` — verified by actually clicking a node in the browser and confirming it navigated to the right project page.
- **Skill/concept nodes with zero evidence are dropped** from the graph after construction (same filter as the `/book-index` page) — `skills.yaml`/`concepts.yaml` entries nobody's `stack`/`concepts`/`<Term>` actually references don't appear as orphan nodes.
- **Organization nodes come only from `experience.yaml`** (RFC, Happy City Hub, Talan Tunisie, FelCloud, Attijari Bank) — education/leadership orgs (ESPRIT, Global UGRAD, AIESEC) aren't modelled as graph nodes yet, a scoping choice, not a bug: the site's prose already covers them in full, the graph is a supplementary map that doesn't need to be exhaustive, and nothing about them is fabricated by the omission.
- All of the above verified live: real edges rendering after the fix, isolated chapters staying on-canvas, click-to-navigate, the search box dimming/highlighting a matched node (typed "langgraph", only the LangGraph node stayed at full opacity with its label shown), and the accessible `GraphList` fallback showing the same connections as plain, linked text.

Chapter bodies pass `chapterNumber`; project/study section bodies don't (their prose headers — "TL;DR", "Problem & constraints" — aren't sub-numbered per docs/07, the section itself is already "§3.1").
- **`/index` collides with the static export's own root `index.html` on real static file servers** — confirmed by serving the build with `serve` and finding `/index` returned the Cover page, not the Index page. Renamed the route to `/book-index` (docs/05 literally specifies `/index`; deviation logged, reasoning in `src/app/book-index/page.tsx`'s comment). The same ambiguity is expected on Vercel, docs/05's deploy target.
- **Drop cap scope bug caught in visual QA**: `.chapter-article > p:first-of-type` also matched project/section pages (which share the same layout component), putting a drop cap on the first paragraph of "Problem & constraints" — not an opening paragraph. Fixed with an explicit `dropCap` prop on `ChapterLayout`, true only for actual chapter pages.
- **Skim mode hides prose, not headings.** Docs/04 says "long prose" is hidden — headings stay visible so Skim mode reads as a compact outline rather than a wall of collapsed sections. `.skim-hide` is applied per-element (p/ul/ol/table/Figure/MarginNote) in `mdx-components.tsx`, not as a wrapper around the whole body, so KeyFacts/Timeline/SkillGroups/ProjectHero/ResultsBlock (plain React, not routed through the MDX component map) stay visible unconditionally — verified live in the browser: toggling Skim mode on a project page kept the hero and collapsed everything else to headings only.
- **`react-hooks/set-state-in-effect` came up three more times** (ContinueReading, SearchModal ×2) — same class of issue as Phase 2's ThemeToggle. Fixed by (a) `useSyncExternalStore` for reading an external source (localStorage) on mount — `ContinueReading` — and (b) restructuring `SearchModal` to derive "should results be visible" from render-time state (`trimmed.length >= 2`) instead of clearing state reactively, plus a `key`-based remount from the parent (`KeyboardShortcuts`) instead of a reset-on-close effect.
- **Pagefind + bundler**: `import('/pagefind/pagefind.js')` doesn't exist at build time (Pagefind indexes `out/` *after* `next build`), so a static `import()` would fail bundler analysis. `lib/pagefind.ts` builds the import via `new Function('path','return import(path)')` — invisible to the bundler, resolved only at runtime in the browser. Verified working end-to-end against the real static build (search for "guardrail" correctly surfaced 3 pages with highlighted excerpts); gracefully reports "not available" under `next dev`, where the Pagefind bundle doesn't exist yet.
- **Backlinks are real, not just forward `related`.** `lib/backlinks.ts` scans every chapter's and section's raw MDX for markdown links pointing at a given route, plus the `related` frontmatter run in reverse — verified live: Chapter VI's new real link to Chapter II produces a "Connections → VI. Recognition & Community" backlink on Chapter II's own page, with no `related` entry needed on either side.

Converted to real Markdown links to the closest addressable route (`/chapters/2` — Timeline entries aren't individually routable yet — and `/chapters/3/agrisense-ai`).

## Phase 2 implementation notes
- **Hydration**: the pre-paint theme script (`lib/theme.ts`) mutates `<html data-theme>` outside React's render, which is the standard dark-mode pattern but trips React's hydration diff — fixed with `suppressHydrationWarning` on `<html>` and `<body>` (the latter also silences a real-world false positive from the Grammarly browser extension injecting `data-gr-ext-installed` etc. before hydration).
- **Theme default bug caught in visual QA**: the first `themeInitScript` fell back to `prefers-color-scheme: dark` when no stored preference existed, so a dark-mode OS defaulted the whole site to Night reading — contradicts docs/04 ("light is the default because books are read on paper"). Fixed: light unless the reader has explicitly toggled dark (localStorage only, no system-preference fallback).
- **Layout width bug caught in visual QA**: `.chapter-grid`'s `max-w-6xl` (1152px) was narrower than TOC(200px) + gap(3rem) + article(70ch text + 300px margin-note float reserve) ≈ 1248px, so the margin-note space would have been squeezed/clipped on very wide viewports. Fixed by sizing `.chapter-grid` itself (720px single-column default, 1280px at ≥1200px) instead of a generic Tailwind max-width utility.
- **No Radix/shadcn dependency added.** Sidenote and the mobile Contents drawer use native `<details>`/`<summary>` — fully accessible and keyboard-operable with zero JS. Still deferred; only add Radix if a concrete future need (e.g. Map hover cards in Phase 4) can't be done natively.
- **Drop caps are automatic**, not per-chapter markup: `.chapter-article > p:first-of-type::first-letter` in `globals.css` targets the first real body paragraph of every chapter (ChapterOpener's abstract lives in a `<header>`, so it's correctly skipped).
- **`ProjectHero` initially dropped two frontmatter fields** (`trace`, `context`) that were captured in content but never rendered — caught by grepping the built `out/` HTML for expected strings, not just by "the build passed." Fixed; a reminder that a green build only proves the pipeline works, not that every field made it to the page.
- **Responsive verification**: `resize_window` doesn't actually resize the browser viewport in this sandbox (window stays pinned to the host's screen resolution) — confirmed 360px/768px breakpoints instead via an injected iframe of the target width plus `getComputedStyle`/`getBoundingClientRect` checks (grid columns, TOC visibility, no horizontal overflow), and confirmed the wide/desktop layout by direct screenshot at the host's native ~1536–1568px width (comfortably ≥1200px). 1920px specifically wasn't visually screenshotted (iframe technique became unreliable after repeated reloads) — the desktop breakpoint's CSS was verified at 1920px via computed styles before that, and Phase 5's Playwright audit will cover exact-pixel 360/768/1280/1920 screenshots properly.
- **Skim mode, live TOC progress ribbon, and full backlink discovery (Connections beyond the explicit `related` field) are Phase 3 work**, not Phase 2 — docs/05 assigns numbering/Index/Skim mode to Phase 3 explicitly.
